# 系统架构与核心拓扑 (Architecture & Topology)

## 1. 架构总览

系统采用严格解耦的三层分层架构，全链路保证在 30 秒烧绳倒计时内输出极低延迟（< 15ms）的高质量决策：

```
+-----------------------------------------------------------------------------------+
|                              炉石传说客户端 (Unity / Windows)                     |
+-----------------------------------------------------------------------------------+
                                          |
                         (官方调试流输出, 0ms 延迟, 零注入)
                                          v
+-----------------------------------------------------------------------------------+
| 【数据层】Power.log 流式状态机 (Data Ingestion Layer)                             |
|  - 实时监听 %LocalAppData%\Blizzard\Hearthstone\Logs\Power.log                    |
|  - 映射开源 HearthDb 官方元数据，还原 EntityID、随从属性、手牌、酒馆随从、金币、星级 |
+-----------------------------------------------------------------------------------+
                                          |
                               (盘面结构化张量 / JSON)
                                          v
+-----------------------------------------------------------------------------------+
| 【决策大脑】双模动态决策引擎 (Dual-Engine Decision Brain)                          |
|                                                                                   |
|  [模式 A · 生产级基石] 贝叶斯流派后验 + 蒙特卡洛生死线 + 组合背包动态规划 (DP)       |
|    - 耗时: < 5ms  |  对标万分准确率: 85%+  |  版本更新冷启动: 0 毫秒                |
|                                                                                   |
|  [模式 B · 进阶增强] Set Transformer 跨实体自注意力 + 高分段 Replay 模仿学习         |
|    - 耗时: 50~100ms | 对标万分准确率: 90%+  |  机制语义向量化 (Zero-Shot)          |
+-----------------------------------------------------------------------------------+
                                          |
                               (决策推荐 Action 序列)
                                          v
+-----------------------------------------------------------------------------------+
| 【表现层】Windows 透明点击穿透 HUD (Presentation Layer)                            |
|  - Win32 API (WS_EX_TRANSPARENT | WS_EX_LAYERED)，完全不干扰玩家鼠标出牌           |
|  - 随从卡面上浮动态推荐 Badge（高亮对子、核心怪、战力评分）                         |
```

## 2. 数据流动契约与时延预算 (Latency Budget)

回合内单次状态变更（如买怪、刷新、打出）的全链路处理时延预算如下：

| 阶段 | 职责说明 | 目标延迟 | 失败降级策略 |
| :--- | :--- | :--- | :--- |
| **数据捕获** | `Power.log` 增量读取与行模式匹配 | $\le 2\text{ ms}$ | 仅处理关键 TAG_CHANGE，跳过不关心的音频/动画事件 |
| **状态还原** | 实体（Entities）状态机组装与酒馆快照 | $\le 3\text{ ms}$ | 内存脏标记差量更新 |
| **决策计算** | 双模算法求解（贝叶斯 + DP 背包求解） | $\le 5\text{ ms}$ | 深度限制与分支剪枝，5ms 阈值超时强制返回局部最优 |
| **HUD 渲染** | WPF / Webview2 渲染悬浮提示层 | $\le 5\text{ ms}$ | 硬件加速绘制，避免复杂滤镜重绘 |
| **总计** | 完整事件响应周期 | $\le 15\text{ ms}$ | 远低于人类反应极限（约 200ms），绝不卡顿 |

## 3. 版本更迭 (Meta Drift) 应对策略

- **数据层解耦**：所有卡牌元数据通过 `HearthDb` 与外部 `cards.json` 维护，版本削弱身材无需重新编译。
- **算法层冷启动**：
  - Day 0：降级到基于规则与背包 DP 的模式 A，更新配置即刻可用。
  - Day 1-2：自动抓取天梯高分局胜率矩阵，动态注入贝叶斯单卡权重。
  - Day 3：使用少量高分录像微调模式 B 的 LoRA 适配层。
