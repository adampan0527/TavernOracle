技术架构专题 · REPORT 004

方案 A 深度拆解：TavernOracle 的 HDT 插件实现方案

解答“方案 A 是否做成 HDT 插件”、剖析 HDT 宿主机制、复用四大开源基建与 1~2 周极速落地逻辑

1. 核心定性：是的，方案 A 就是基于 HDT 的 C# 插件

🎯 明确回答

是的，技术栈的方案 A 正是将 TavernOracle（酒馆先知）开发为一款基于 C# (.NET) 的 Hearthstone Deck Tracker (HDT) 官方扩展插件（Plugin DLL）。

用户只需将编译生成的 TavernOracle.dll 放入 HDT 的 Plugins/ 文件夹，启动 HDT 时即可自动加载并生效，直接在游戏画面上挂载智能战术 HUD。

2. 为什么方案 A 是首选推荐？——站在开源巨人的肩膀上

开发一款酒馆战棋辅助系统，如果完全从零起步，开发团队通常需要花费 $70\%$ 以上的精力 去解决各种杂乱的底层工程边缘问题（如解析错乱的日志、跟进暴雪补丁卡牌变化、处理 Windows 缩放与游戏窗口吸附）。而 HDT（由知名炉石社区团队 HearthSim 维护）已经开源了历经数年打磨的工业级基建：

基建 01 · 官方级数据元
HearthDb
全语言卡牌元数据库，随从种族、星级、身材、法术、技能、三连金卡映射一应俱全，版本更新自动拉取。
避免从零维护卡牌库
基建 02 · 极速日志流
LogWatcher
高容错异步读取 Power.log，自动处理日志截断、网络重连、区域切换与 TagChange 事件广播。
零延迟状态还原
基建 03 · 战斗仿真引擎
Bob's Buddy
HDT 原生内置千次蒙特卡洛战力模拟模块！插件可直接获取下回合暴毙率 $P_{\text{lethal}}$，无需自写战斗引擎。
免写数万行模拟代码
基建 04 · 原生穿透窗体
OverlayCanvas
HDT 成熟的 WPF 穿透与吸附系统，完美解决游戏全屏/窗口化、分辨率缩放、DPI 适配与 WS_EX_TRANSPARENT。
零渲染闪烁与坐标偏移
🚀 投资回报比（ROI）结论： 采用 HDT 插件方案，开发者只需编写最核心的 “双模决策大脑”（贝叶斯后验 + 背包 DP），1~2 周即可交付高分段可用的 MVP；而独立客户端则需 3~4 周造轮子。

3. HDT 插件的工程实现机制 (How It Works)

HDT 采用标准的 C# MEF 插件架构。开发 TavernOracle 只需引用 HDT 的核心类库并实现 IPlugin 接口：

using Hearthstone_Deck_Tracker.Plugins; using Hearthstone_Deck_Tracker.API; using System.Windows.Controls; namespace TavernOracle { public class TavernOraclePlugin : IPlugin { public string Name => "TavernOracle (酒馆先知)"; public string Description => "酒馆战棋实时万分级战术参谋长 HUD"; public string ButtonText => "先知设置"; public string Author => "TavernOracle Team"; public Version Version => new Version(1, 0, 0); public MenuItem MenuItem => null; private OracleDecisionEngine _engine; private TavernHudOverlay _hudOverlay; public void OnLoad() { _engine = new OracleDecisionEngine(); _hudOverlay = new TavernHudOverlay(); // 1. 将自定义 HUD 控件直接挂载至 HDT 的游戏透明覆盖层 (OverlayCanvas) Core.OverlayCanvas.Children.Add(_hudOverlay); // 2. 订阅 HDT 现成的游戏事件 (完全无需手动逐行读文件) GameEvents.OnTurnStart.Add(OnTurnStart); GameEvents.OnGameEnd.Add(OnGameEnd); } private void OnTurnStart(ActivePlayer player) { // 3. 直接读取 HDT 封装好的当前盘面实体、手牌与酒馆随从 var board = Core.Game.Player.Board; var hand = Core.Game.Player.Hand; var gold = Core.Game.Player.Resources; // 4. 读取 Bob's Buddy 预估的下一场暴毙概率 P_lethal float pLethal = BobsBuddyInvoker.GetNextCombatLethalOdds(); // 5. 执行核心背包 DP 求解 (耗时 ≤ 5ms) var actions = _engine.SolveOptimalSequence(board, hand, gold, pLethal); // 6. 刷新头顶微标与顶部横条 _hudOverlay.RenderRecommendations(actions); } public void OnUnload() => Core.OverlayCanvas.Children.Remove(_hudOverlay); public void OnUpdate() { } } }

4. 方案 A vs 方案 B：选型全方位对比

为满足不同场景的需求，项目规划了清晰的演进阶梯：

对比维度 方案 A · HDT 插件 (C# .NET) 方案 B · 独立客户端 (Rust + Tauri)
定位与角色 MVP 首发主干路线（最快上线） 长期进阶路线（打造独立品牌）
开发落地周期 1 ~ 2 周即可天梯实战 3 ~ 4 周从零构建底层
宿主依赖 强依赖 HDT 进程（用户电脑必须开着 HDT） 零宿主依赖，独立 .exe 安装包
日志与卡牌库 直接复用 HearthDb 与 LogWatcher 需自行维护 Power.log 状态机与 cards.json
战力模拟器 直接复用 HDT 内置的 Bob's Buddy 千次对战模拟 需自行移植或重写战斗模拟核心
UI 表现力 WPF 矢量控件（传统成熟，暗黑卡牌质感） Webview2 (Vue 3/Tailwind/CSS3) 现代极客毛玻璃
用户推广门槛 极低（硬核炉石玩家 90%+ 电脑里本来就有 HDT） 需让玩家单独下载安装并信任新软件
