# Visual Reports & Demos (交互式汇报与演示目录)

本目录专门用于存放向用户进行思路汇报、方案设计与动态演练的交互式 HTML 内容。

## 目录组织规范

每个汇报或演示独立成一个子文件夹，统一放置在本目录下：

```text
report_html/
├── README.md
├── 001_example/
│   ├── index.html        # 统一入口文件
│   ├── css/              # 样式资源（可选）
│   ├── js/               # 交互与动画脚本（可选）
│   └── assets/           # 图像、图标等媒体资产（可选）
└── 002_xxx/
    └── index.html
```

## 核心约定

1. **命名规范**：子目录命名格式为 `3位前导零数字_简明英文下划线名称`，例如 `001_knapsack_dp_visualizer`、`002_hud_overlay_prototype`，编号单调递增。
2. **统一入口**：每个子目录必须以 `index.html` 作为主入口。
3. **自包含与高内聚**：所有依赖样式、脚本与媒体资源应归并在各自子文件夹中，确保每个汇报独立可读、便于修改与持久化。
4. **数学公式规范（本地自包含 KaTeX）**：
   - 涉及数学建模或算法公式时，汇报子目录下需内置 `lib/katex/` 资源（css/js/fonts），杜绝裸写未编译的 LaTeX 代码，保证 100% 离线脱机也能完美呈现排版。
5. **CSS 避坑**：文本与标题容器切勿使用 `display: flex; gap: ...`，防止行内数学公式被强制拉扯成独立 flex 项产生断裂空白。
6. **Playwright 强制验收协议**：
   - 所有生成的 HTML 页面，AI Agent 必须在本地使用 Playwright 启动真实浏览器无头渲染测试，截屏核验排版及交互无误后方可交付。
